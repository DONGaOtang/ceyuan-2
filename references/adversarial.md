# 对抗审查规则集

供 Step 4 使用。目标不是挑刺，是找「一戳破、整个结构就塌」的根本缺陷。

## 一、Steelman 先行（防稻草人）

审查前，先把自己方案说到最强版本——说到「拥护者会点头说：对，这就是我的方案」。再攻击这个最强版。

**禁止**：攻击一个弱化版/曲解版，然后宣布自己赢了。那是自嗨，不是审查。

**检验**：反证打出来后，方案提出者能不能说「这不是我的意思」？能说，说明你打了稻草人。

## 二、攻击角度清单（15 个）

每个视角一句攻击话术，逐条过一遍，别跳。**每条反证必须标注依据**：是事实（引用户口碑/数据）还是推测，推测必须标「待验证」，不许凭直觉口嗨。

| # | 攻击视角 | 攻击话术 |
|---|---|---|
| 1 | 凭什么来 | 受众有非来不可的理由吗？ |
| 2 | 传播不出去 | 有值得截图转发的点吗？社交货币在哪？ |
| 3 | 预算错配 | 钱花在了不产生结果的地方吗？ |
| 4 | 执行翻车 | 天气/供应商/现场事故，哪个环节会崩？ |
| 5 | 合规风险 | 报批、消防、食品酒类、广告法、版权，漏了吗？ |
| 6 | 效果难衡量 | 热闹完能归因到结果吗？还是自嗨一场？ |
| 7 | 动机错配 | 这活动满足的是真需求，还是假象？ |
| 8 | 创意自嗨 | 甲方觉得好，受众无感，怎么办？ |
| 9 | 时机错配 | 时间窗口差吗？跟竞品扎堆了吗？ |
| 10 | 资源错配 | 人力/物料/时间够吗？谁来做？ |
| 11 | 假设不成立 | 哪些 Soft/Assumption 被当成了 Hard？ |
| 12 | 二阶效应 | 会不会引发负面舆论、后续麻烦？ |
| 13 | 前提不成立 | 这个活动本身一定要办吗？不办活动能不能达成目标？ |
| 14 | 维度冲突 / 缺失 | 确认的维度全被承载了吗？有没有显眼维度挤掉了其他维度（如促销挤掉品牌演绎）？维度之间打架了吗？ |
| 15 | 推导路径定位错 | 推导路径（七状态→对象→形态→时空）定位对了吗？「这个活动真的是身份确认，还是其实想卖货（行为）」？类型定位错了，方案全错。 |

## 三、收敛 + 严重度排序

- **多个角度独立打中同一弱点** = 关键发现，必改。
- **孤立冷门洞察** = 噪音，可忽略。
- **根本缺陷** = 那个「一戳破整个结构就塌」的致命假设，只找这一个，不贪多。

输出排序：从「能毁掉整个活动」到「锦上添花」降序排。

## 四、补救方法

每条高严重度缺陷，给**可执行的修法**，不是「注意一下」：

- ❌ 「注意现场安全」 → 空话。
- ✅ 「增配 2 名持证安保 + 提前 48h 消防预检 + 应急预案 A/B」 → 可执行。

修法要能落到：加什么机制、换什么动作、删什么环节、补什么资源。

## 五、审查终局三问

1. 修完后，那个根本缺陷还成立吗？
2. 用户还没确认，你能替用户下这个判断吗？（不能）
3. 还有没有「大家礼貌性不提」但很致命的问题？
