# 工作范围、报价边界、验收与变更

正式提案、乙方交付、招商赞助、跨部门协作必须写边界。没有边界，方案越完整，后续越容易失控。

## 一、工作范围

格式：

| 模块 | 我方负责 | 甲方/用户负责 | 第三方负责 | 待确认 |
|---|---|---|---|---|
| 策划 | 主题、机制、流程、方案 | 业务目标、品牌资料、审批 |  |  |
| 设计 | 主视觉方向、物料清单 | 品牌规范、素材授权 | 设计供应商 |  |
| 执行 | 排期、统筹、现场管理 | 场地/嘉宾/内部协调 | 搭建/AV/摄影 |  |
| 传播 | 内容规划、话术、节奏 | 官方账号权限、审核 | 达人/媒体 |  |
| 复盘 | 数据模板、复盘报告 | 实际数据、销售反馈 |  |  |

表中分工是范围示例，不能当作任何项目已承诺的工作。按已确认 brief 写清实际要交付的是概念、决策、执行、传播、招商或复盘中的哪些内容，以及读者、成熟度、格式、修改范围和交付时间；需求到真实文件的追踪沿用 `proposal-schema.md` 附录索引规则。用户明确只要一个文件或局部内容时，不以默认全案扩张范围。

“我方负责策划”须包含已授权的实质创作，不把故事正文、环节介绍、规则细则留给甲方填写；“甲方提供资料”须指具体事实和授权。不同内容可合并交付，但对外阅读内容与内部决策记录仍保持边界。未生成的附件、未完成的设计、未确认的资源必须分别标识。

文件范围沿用 `triage-router.md` 的同一记录，不再建文件大全：区分本次必交、依具体条件触发及明确未纳入项。标准依据分别记录客户正式brief/合同或招标模板、经核实的适用要求/主办或场地提交规范、历史项目范例、平台样本与本次拟定建议；不能把后三类自动升级为前两类。发生冲突时标出具体条款、版本和影响，在原有确认点解决。原生编辑文件、阅读导出版和参考素材是否包含应明确；渲染图、视觉简报、制作源件与施工图是不同完成程度。

## 二、不包含事项

正式提案必须列“不包含”，尤其乙方场景。

常见不包含：
- 第三方采购费用。
- 媒体投放费用。
- 达人合作费用。
- 场地租赁费用。
- 搭建、AV、摄影摄像。
- 政府审批代办。
- 超出轮次的设计/方案修改。
- 活动后长期运营。

不要写得像推责，要写成“本次报价/范围不包含，可按需另行报价或确认”。

## 三、甲方配合事项

必须写：
- 品牌资料。
- 历史活动数据。
- 目标人群名单或邀约池。
- 预算上限。
- 审批人和审批周期。
- 嘉宾、媒体、政府关系。
- 法务、合规、财务对接人。
- 反馈时间。

每项都写截止时间。不写时间等于没有责任。

## 四、报价逻辑

乙方/赞助/招商场景按需写：

| 项目 | 说明 |
|---|---|
| 策划服务费 | 策略、创意、方案、流程、统筹 |
| 执行管理费 | 供应商协调、现场管理、项目管理 |
| 第三方费用 | 场地、搭建、AV、摄影、物料、餐饮 |
| 媒体/达人费用 | 投放、达人、KOL、通稿 |
| 应急金 | 默认 10%，大型或户外活动可提高 |
| 可选项 | 直播、摄影升级、嘉宾邀约、额外物料 |

预算必须算术自检：执行费用分项小计 + 应急金 = 含应急金总额；应急金若已列入分项不可重复相加，税费/服务费/可选项注明含或不含。比例为初始测算假设，必须说明计算基数和本项目取值依据，不冒充已确认报价。

## 五、验收标准

| 交付物 | 验收标准 |
|---|---|
| 策划方案 | 按 brief 覆盖实际问题、活动内容、目标、机制及单元关系，读者不靠口头补充能作出本阶段判断；执行承诺须有可核对的资源与预算 |
| 执行表 | 时间、地点、负责人、物料、费用、依赖和交接动作明确；配套规则/串词/技术指令按范围已交，不要求执行者重新策划 |
| 设计物料 | 约定成品真实存在，内容、格式、数量、交付时间匹配；制作尺寸与规格有场地/供应商确认，方向图不能冒充制作稿 |
| 现场执行 | 按 Run of Show 完成，异常有记录 |
| 传播内容 | 区分规划与成品，约定文案/脚本/素材已实际生成；数量、平台、发布口径、发布时间、素材格式与授权状态可核对 |
| 复盘报告 | 目标 vs 实际、指标口径、实际数据来源、偏差与可执行建议；缺数据列未知，计划表不能冒充已发生结果 |
| 概念案 | 活动介绍、概念故事或价值逻辑、主要单元、参与体验、前后/并行关系和必要参考完整；可为创作拟案，不强求未到阶段的采购与执行表 |
| 决策/汇报稿 | 本次决策问题、建议、关键依据、可选取舍、投入和未决事项清楚；不以故事篇幅代替决策所需证据 |
| 招商/赞助稿 | 合作对象收益、权益库存、兑现方式、限制/排他、报价口径、履约证明和资源状态一致；拟邀/拟售不得写为已签/已锁定 |

验收不等于保证商业结果。商业结果受预算、用户资源、外部环境和执行配合影响，需在方案里写清可控与不可控边界。

上述是不同用途的验收条件，不是每项目强制交八类文件。验收同时查看内容是否充分、文件是否真实可读和本次用途是否可用。缺少审批/资源不必否定完整概念拟案，但依赖未核实的执行稿不能标“可直接执行”；最终稿、创作完成、商务确认、技术确认和审批状态须分别表达。未知事项只有不妨碍本次用途且已绑定责任/时间时才可随稿保留。

## 六、变更机制

必须写：
- 变更提出人。
- 变更影响评估：时间、预算、质量、风险。
- 追加费用规则。
- 截止节点：活动日前多少天后不接受重大变更。
- 紧急变更审批人。

常见判定：
- 主题方向重改 = 重大变更。
- 增加活动环节 = 范围变更。
- 增加物料数量 = 成本变更。
- 延迟反馈导致延期 = 核对约定反馈节点、实际影响和双方义务后确定责任，不能仅凭延迟自动归责甲方。
- 政策/天气/不可控因素 = 双方协商调整。

## 七、取消与延期

大型活动或乙方提案建议写：
- 已发生第三方成本按实际合同、订单与可退范围处理，不笼统承诺全部不可退。
- 已完成策划/设计/统筹按阶段验收。
- 延期需重新确认供应商档期与费用。
- 户外、政企、大型活动需明确不可抗力处理。

## 八、边界写法原则

- 清楚，但不敌对。
- 保护交付质量，而不是逃避责任。
- 每个待确认都绑定负责人和时间。
- 每个不包含项按能力、授权和实际商务条件判断能否转为可选报价。
