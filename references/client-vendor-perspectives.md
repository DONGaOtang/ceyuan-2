# 甲乙方与提案口径

同一场活动，甲方和乙方的方案逻辑不同。不能混写成“看似公平，实际谁也保护不了”的空话。

## 一、甲方模式

适用：用户要给老板、领导、内部市场部、业务负责人看。

甲方关心：

| 模块 | 必须回答 |
|---|---|
| 业务问题 | 为什么要办，不办会怎样 |
| 目标判据 | 怎么证明活动有效 |
| 预算合理性 | 钱花在哪，哪些不能砍，哪些可降级 |
| 内部资源 | 需要销售、运营、行政、法务、老板提供什么 |
| 风险责任 | 到场、舆情、合规、供应商、预算超支谁兜底 |
| 汇报可读性 | 老板能否快速看懂亮点和风险 |

甲方方案写法：
- 先写业务问题和目标，不先写主题。
- 预算要解释取舍，不只列金额。
- 风险要写真实风险，不写“加强管理”。
- 待确认事项要指向内部决策。

## 二、乙方模式

适用：用户是策划公司、广告公司、执行公司、咨询方，要给客户提案或报价。

乙方关心：

| 模块 | 必须回答 |
|---|---|
| 提案差异化 | 为什么不是模板方案 |
| 工作范围 | 我方负责什么 |
| 甲方配合 | 甲方需提供资料、审批、资源、反馈 |
| 不包含项 | 哪些不在本次报价内 |
| 报价逻辑 | 成本、服务费、第三方费用、应急金 |
| 验收标准 | 交付到什么程度算完成 |
| 变更机制 | 超范围、延期、反复修改如何处理 |

乙方方案写法：
- 创意亮点要更靠前，但不能牺牲边界。
- 正式提案必须有“工作范围与边界”。
- 预算表要区分我方服务费、第三方代采、可选项。
- 所有待确认事项都要绑定甲方责任。
- 竞标、比稿、客户多方比较时必须加 Pitch Battle 页面，说明竞品提案预判、我方制胜点、老板打动点、压价应对和成交话术。

必读：乙方提案、竞标、比稿、招商赞助场景加载 `pitch-battle.md`。没有 Pitch Battle 页面，只能算“能上交”，不能算“有中标力”。

## 三、内部协同模式

适用：企业内部市场、HR、行政、销售、品牌、运营共同推进。

重点：
- RACI 分工。
- 决策节点。
- 内部资源需求。
- 跨部门风险。
- 活动后数据归属。

输出必须有：分工表、时间线、需求清单、审批节点。

## 四、招商赞助模式

适用：赞助、招商、合作方提案、展位销售、资源置换。

重点：
- 对方为什么投入。
- 权益包如何分层。
- 曝光、线索、销售、背书如何交付。
- 权益交付如何验收。

输出必须有：
- 赞助商收益。
- 权益包和报价梯度。
- 曝光资源清单。
- 交付范围。
- 合作条款和下一步 CTA。
- Pitch Battle 页面：其他合作方案可能怎么写，我方权益和资源为什么更值得投。

## 五、政企/To G 模式

适用：政府、园区、协会、国企、公共事务、招商引资、签约仪式。

重点：
- 规格与秩序优先于“炸裂创意”。
- 口径一致优先于平台热度。
- 审批和公共价值优先于互动玩法。

输出必须有：
- 活动规格。
- 领导/嘉宾动线。
- 座次和仪式动作。
- 媒体通稿口径。
- 审批与合规清单。
- 公共价值表达。

禁区：
- 不随意做公开口径 AB 测试。
- 不为了传播制造冲突。
- 不写未经确认的政策承诺。
