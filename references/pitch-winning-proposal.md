# 中标型正式提案增强

本文件解决一个问题：方案合理，不等于客户愿意拍板。高预算、乙方竞标、老板过会、文化艺术、文旅节庆、城市事件、品牌年度项目，必须把「完整方案」升级成「中标型提案」。

## 一、触发条件

命中任一条即触发：

- 预算达到 100 万以上，或用户明确提到大预算、高预算、报价、压价、贵在哪里。
- 用户要给甲方、老板、领导、评审会、比稿会、采购会看。
- 项目需要成为年度事件、城市事件、品牌事件、节庆主线或传播战役。
- 方案中有 4 个以上并列模块，容易被看成零散服务清单。
- 传播由外部公司、媒体公司、达人/KOL 团队或甲方传播部门承接。

若触发原因是文旅、艺术文化、海边社区或阿那亚类项目，必须先按 `culture-tourism-boundary.md` 确认场景命中，再叠加 `culture-tourism-strong-narrative.md`。高预算或老板过会本身不等于文旅强叙事。

## 二、中标型提案五个硬门禁

正式成案前必须逐项回答。任一项缺失，判为「能上交但中标力不足」。

| 门禁 | 必须产出 | 不合格表现 |
|---|---|---|
| 强问题定义 | 前 3 页有一句锋利判断，指出客户真正的痛 | 只写背景、趋势、调性，不敢下判断 |
| 年度级记忆点 | 1 个老板能复述的峰值事件或主场面 | 多个温和模块平铺，没有被记住的瞬间 |
| 模块主次关系 | 核心主模块 / 体验支撑模块 / 口碑沉淀模块 | 六七个模块并列，资源不知道押在哪 |
| 预算价值架构 | 把报价解释成 2-4 套系统价值 | 只按物料、人员、单模块列费用 |
| 传播协同接口 | 每日/每阶段给传播方什么素材、格式、数量、责任人 | 只写平台矩阵，不像外包可接的 brief |

## 三、强问题定义

开篇不只解释项目，而要重定义问题。

格式：

```
这次项目真正要解决的不是____，而是____。
过去客户容易被误解为____；本方案要证明____。
所以本届/本场/本次不应继续____，而应____。
```

要求：

- 句子必须能放进前 3 页。
- 要回应客户的真实压力：争议、预算、增长、口碑、审美、组织协同、老板认可。
- 不要为了锋利而冒犯客户。锋利指问题定义准确，不是措辞刺耳。

## 四、年度级记忆点

高预算或年度项目必须有一个主事件。它可以是开幕、闭幕、首次出现、全城联动、限定仪式、集体行动、夜间发生或公开档案发布。

输出格式：

| 字段 | 写法 |
|---|---|
| 主事件名 | 8-16 字，能被老板和媒体复述 |
| 发生时间 | 开幕 / 高峰日 / 闭幕 / 每日固定时刻 |
| 发生地点 | 具体到点位、线路或空间类型 |
| 现场动作 | 谁在何时做什么，观众看见什么 |
| 传播画面 | 一句话描述短视频/照片第一眼 |
| 预算支撑 | 它消耗哪些费用，为什么不能砍 |
| 风险降级 | 天气、人流、审批、演员、舆情出问题时怎么降级 |

判定标准：客户老板听完 30 秒，能不能向别人复述「这一届最不一样的地方」。不能复述，就不是年度级记忆点。

## 五、模块主次关系

超过 4 个模块时，不允许平铺。必须分层：

| 层级 | 定义 | 预算原则 |
|---|---|---|
| 核心主模块 | 直接承载 Big Idea 和年度记忆点 | 不轻易砍，砍掉方案会失去差异 |
| 体验支撑模块 | 帮用户进入、理解、移动、参与 | 可降规格，不可断链 |
| 口碑沉淀模块 | 形成传播、复盘、内容资产和长期证据 | 可调数量，不可没有出口 |

每个模块都要标注：服务哪一层用户旅程、驱动哪一个指标、依赖谁配合、砍掉会损失什么。

## 六、预算价值架构

大预算不要只按模块报价。必须先给价值系统，再给明细。

格式：

| 系统 | 包含模块 | 解决的问题 | 预算占比 | 价值证明 |
|---|---|---|---|---|
| 进入系统 | 入口、导读、地图、动线、邀约 | 用户如何进入体验 |  | 到场质量、投诉下降、理解成本下降 |
| 发生系统 | 峰值事件、现场动作、仪式、互动 | 为什么必须到现场 |  | 参与率、现场停留、社交传播 |
| 资产系统 | 影像、音频、UGC、KOL、档案、复盘 | 活动结束后留下什么 |  | 内容数量、可复用素材、舆情证据 |
| 保障系统 | 项目管理、人员、合规、应急 | 怎么保证不翻车 |  | 准时交付、事故率、应急记录 |

报价解释必须回答：

- 这笔钱买的是哪套系统，不是哪个孤立物料。
- 哪些钱花在「可见体验」，哪些钱花在「不可见保障」。
- 哪些是不可砍项，砍掉会影响哪层指标。
- 哪些是可降级项，降级后损失什么。

## 七、传播外包接口

只写平台矩阵不够。正式提案要给传播方可接的素材接口。

日更型活动输出：

| 每日交付物 | 数量 | 格式 | 来源模块 | 交付时间 | 责任人 |
|---|---:|---|---|---|---|
| 今日地图/导览图 | 1 张 | 海报/长图/小红书图文底稿 | 地图/动线 | 每日 10:00 前 |  |
| 现场短视频素材 | 3-5 条 | 15-60 秒粗剪/原片索引 | 峰值事件/现场动作 | 每日 18:00 前 |  |
| 金句/评论摘录 | 3-5 条 | 文字卡/字幕稿 | 嘉宾/短评/观众 | 每日 20:00 前 |  |
| UGC/观众回声精选 | 10 条 | 文本/截图授权记录 | 观众互动 | 每日 22:00 前 |  |
| 音频/直播切片 | 1-2 条 | 音频/视频片段 | 电台/直播/访谈 | 次日 12:00 前 |  |
| 明日预告文案 | 1 组 | 标题、正文、CTA | 次日排期 | 每日 21:00 前 |  |

非日更活动改成预热期、活动日、活动后 72 小时三段接口。

## 八、终审评分

Step 9 终审必须给 100 分制中标力评分：

| 维度 | 分值 |
|---|---:|
| 问题定义锋利度 | 20 |
| 年度级记忆点 | 20 |
| 模块主次与资源押注 | 15 |
| 预算价值感 | 20 |
| 传播协同可接度 | 15 |
| 执行可信度 | 10 |

低于 80 分，不得判「可上交」。70-79 分只能判「小修后上交」。低于 70 分判「需重做关键模块」。
