# 活动方案最终结构模板

供 Step 5 输出完整方案时使用。按此结构逐节填，别跳节，别注水。

## 方案骨架（七节）

```
① 一句话 Big Idea
② 目标与传导链判据（含闭环图）
③ 体验设计（用户旅程 + 峰终时刻）
④ 传播设计（前中后 + 渠道矩阵）
⑤ 执行设计（时间线 / 分工 / 物料 / 预算表）
⑥ 风险预案
⑦ 效果评估（四层回填）
```

## ① 一句话 Big Idea

- 一句能脱口而出、能被记住、能被复述的主张。
- 检验：用户听完能不能转述给别人？转述不了，就不是 Big Idea，是描述。
- 格式：`「主题」—— 一句话主张（含情绪或冲突）`

## ② 目标与传导链判据

- 对齐 Step 2 的一句话目标 + 传导链判据。**判据不是并列 KPI，是四层传导链 × 四维测量**（见 `references/metrics-flow.md`）。
- 每个判据必须是**数字**（到场率、转化数、传播量、签约额），且覆盖「数量 + 质量」两维，结果层还要「效率 + 成本」。不许「提升品牌影响力」这种空话。
- **闭环图（强制）**：产出一张「投入 → 中间指标 → 结果指标 → 长线资产」四层传导图，标出主判据在哪层、由哪几个中间指标驱动。根据动机动态生成（卖货重心在结果层，品牌重心在资产层，关系重心在中间层）。
- **推导路径（强制）**：方案开头标注整体推导路径 `[七状态] → [参与者/受益者] → [形态] → [时空]`（见 `references/axes.md` 六），让类型定位可被检查。
- 格式：`目标一句话 + 推导路径 + 传导链判据表（层级 / 指标 / 目标值 / 怎么测）+ 闭环图（mermaid 或 ASCII，docx 里转表格）`

## ③ 体验设计

- **用户旅程**：从「收到邀请」到「离场后 3 天」，分节点写每个时刻用户看到/听到/感到什么。
- **峰值时刻**：设计 1 个「几年后还记得」的高峰瞬间（对齐心理机制）。
- **终值时刻**：设计体面收尾（离场小礼物、离场情绪、离场动作），峰终定律决定记忆。
- 格式：`时间轴表（节点 / 用户动作 / 设计动作 / 踩中的心理机制）`

## ④ 传播设计

- **前**：怎么造期待（悬念、预热、KOL 预告）。
- **中**：怎么让到场的人自发传播（打卡点、社交货币、实时话题）。
- **后**：怎么二次发酵（物料复盘、长尾内容、UGC 沉淀）。
- **渠道矩阵**：每个渠道（小红书/抖音/微博/微信/B站/线下）配什么内容、什么节奏。
- 格式：`三阶段表 + 渠道矩阵表`

## ⑤ 执行设计

- **时间线**：从今天到活动日，倒排关键节点（T-30 定场地 → T-14 物料 → T-3 彩排 → D-day）。
- **分工**：每个环节一个负责人 + 一个兜底人（RACI 简版）。
- **物料清单**：每个物料 + 数量 + 到位时间。
- **预算表**：分项（场地/搭建/AV/餐饮/嘉宾/宣传/人员/应急）→ 加总 → 应急金比例（默认 10%）。分项侧重参考 `references/industries.md` 的「预算结构」列，别拍脑袋分。
- 格式：`倒排时间表 + 分工表 + 物料表 + 预算表`

## ⑥ 风险预案

- 从 Step 4 对抗审查的高严重度缺陷直接搬运，每条配预案。
- 每条风险：`风险 / 概率 / 影响 / 预案 A / 预案 B`。
- 至少覆盖：天气、供应商、现场安全、舆情、到场率不达标。

## ⑦ 效果评估

- 活动后怎么证明「成功判据」达成？每个判据配一个测量方式。
- **四层回填（强制，见 `references/metrics-flow.md` 四）**：复盘时逐层填「目标 vs 实际」——投入层花对了吗 / 中间指标层达标了吗 / 结果指标层主判据赢了吗 / 长线资产层沉淀了什么。**断在哪层，下次就补哪层**。
- **推导路径回填（强制）**：复盘时对一遍「推导路径」——Step 3 定位的类型，实际跑下来还成立吗？定位偏了吗（比如以为是想卖货，实际是想确认身份）？偏了就是「推导路径断点」。
- 复盘模板：`目标 vs 实际 / 差在哪 / 为什么 / 下次怎么改 / 断点在哪层 / 推导路径断点在哪`。
- **长闭环（强制）**：活动结束后，把「目标 vs 实际 + 断点层 + 翻车点 + 推导路径断点 + 创意类型」追加到 `references/event-types.md` 对应活动类型的案例锚点里，供下次 Step 1 / Step 3 检索。不写回 = 这次活动白做，下次从零开始。

## ⑧ 交付格式

- 终审通过后，输出 .docx 交付（借力本地 docx 生成能力，见 `references/skill-routing.md`）。
- docx 内容 = 七节骨架 + 闭环图（四层链转成表格）。markdown 源稿保留，作为 docx 的生成依据。
- 检索不到 docx 能力时，输出 markdown 并明确告知「未生成 docx，可自行转换」。

## 输出纪律

1. **先给最小可执行版本**：轻量活动别套大型活动流程，每个环节先问「能不能砍」。
2. **预算必须算术自检**：分项加总 = 总额 + 应急金，对不上就是算错了。
3. **合规必须联网核实**：报批、消防、许可、广告法，不熟悉的行业别凭印象写。
4. **每节都要能落地**：写到「谁、什么时间、做什么、花多少钱」，不许停留在「要加强」「要重视」。
5. **闭环图必带**：没有四层传导链闭环图的方案，不算完整方案。
6. **推导路径必验**：方案开头有推导路径，结尾验证推导路径没跑偏，没有这两处的方案不算完整。
