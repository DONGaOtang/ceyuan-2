# 活动方案最终结构模板

供 Step 8 输出文字版活动方案时使用。核心原则：**文字版方案不是单一模板，而是按用途裁剪的交付系统。** 先判断交付格式，再选择模块；不要给轻量活动套全案，也不要给正式提案漏掉说服层、执行层、预算风险和验收标准。

Step 8 默认双文件交付：`[项目名]-活动方案.md` 是干净方案，`[项目名]-思考过程.md` 是推导与审计。正式方案不承载方法论展示；思考过程不冒充客户可读方案。

本文件只供 Step 8 使用，不得作为 Step 0-7 的替代输出模板。未完成 Step 0-7 的硬暂停点确认前，即使用户要求“完整方案 / 全案 / 直接写一版”，也不得调用本模板生成完整方案；应先回到 Step 0 分流和信息缺口门禁。

## 一、交付格式分级

进入 Step 8 先选交付格式。若用户没有指定，按活动复杂度和阅读对象默认选择。

| 档位 | 适用场景 | 读者 | 输出重点 |
|---|---|---|---|
| A · 一页创意提案 | 早期沟通、老板先看方向、用户只要创意 | 老板 / 客户 / 内部拍板人 | 快速判断有没有感觉、值不值得继续 |
| B · 标准文字版方案 | 大多数活动策划交付 | 客户 / 市场部 / 项目负责人 | 说清为什么做、怎么做、怎么衡量 |
| C · 全案执行版 | L/XL 大型活动、跨部门协作、供应商落地 | 执行团队 / 供应商 / 项目管理者 | 让团队按表推进，不靠口头解释 |
| D · 对外竞标/招商/赞助提案 | 竞标、赞助招商、政府/合作方提案 | 客户 / 赞助商 / 合作方 / 政企对象 | 说服对方投入钱、资源或背书 |

**裁剪规则**：

- S 轻量活动默认 A 或 B，除非用户明确要执行全案。
- M 标准活动默认 B，按活动类型挂载必要模块。
- L/XL 大型或战役级活动默认 C；若方案用于竞标、招商或赞助，同时叠加 D 的商务模块。
- 用户只要创意，不输出完整长方案，先给 A 档。
- 用户要 docx 时，先完成 Step 9 终审，再把已确认的对应档位 markdown 源稿导出为 docx。docx 导出属于核心流程后的交付格式转换，不得提前替代 Step 8/9。

## 二、A 档 · 一页创意提案

适合快速过方向。控制在一页或 800 字以内。

```
① 活动背景一句话
② 目标一句话
③ Big Idea
④ 3 个核心玩法
⑤ 为什么现在做
⑥ 预期效果
⑦ 最大风险
⑧ 下一步待确认
```

**输出纪律**：

- 不写长执行表。
- 每个玩法必须有现场动作或传播动作。
- 最大风险必须诚实写，不许只写好处。

## 二点五、双文件交付纪律

### 文件 A：干净方案

读者：老板、客户、市场部、执行负责人。目标：快速判断值不值得做、怎么做、谁负责、花多少钱、如何验收。

正文只放：

- 业务问题与机会。
- 活动目标与成功判据。
- Big Idea 与核心机制。
- 用户体验与现场流程。
- 传播与转化承接。
- 执行排期、分工、物料、预算。
- 风险预案、合规要点、待确认事项。
- 效果评估方式。

正文禁止默认放入：

- Step 0-9 过程标题。
- 推导路径和方法论解释。
- 大段事实与假设清单。
- 证据等级表、检索记录、来源审计。
- 利益相关方心理拆解全过程。
- 创意闪卡推导全过程和被否决方向。
- Red Team 原始攻击。
- 完整实验设计表和回填模板。
- “正式方案必备”“无此不算”等系统内训语气。

### 文件 B：思考过程

读者：策划者、复盘者、二次修改者。目标：让方案为什么这么写可追溯、可质疑、可迭代。

思考过程不是长文堆料，而是“摘要 + 决策记录 + 可下钻附录”。默认结构：

```
① 一页决策摘要
② 关键决策记录
③ 风险与验证地图
④ 附录索引
附录 A 事实与假设库
附录 B 证据来源库
附录 C 创意推导与被否方向
附录 D Red Team 与修正记录
附录 E 实验计划与判定表
附录 F 交付一致性检查
```

### ① 一页决策摘要

控制在 800-1200 字或 1 张表内，回答：

- 最终方案为什么选这个方向。
- 最关键的 3 个判断。
- 最大的 3 个风险。
- 还缺哪些信息。
- 哪些内容已经进入正式方案，哪些只保留在附录。

### ② 关键决策记录

按“问题”而不是按 Step 写。每条记录使用固定格式：

| 决策问题 | 最终结论 | 依据 | 最强反方意见 | 为什么仍这样选 | 对方案的影响 | 附录引用 |
|---|---|---|---|---|---|---|

优先记录真正影响方案走向的取舍，例如：目标人群、窗口、主叙事、核心机制、预算分配、数据判据、风险降级。不记录无关思考。

### ③ 风险与验证地图

用一张表替代冗长实验说明：

| 假设/风险 | 影响模块 | 验证动作 | 决策时间 | 成功阈值 | 失败降级 | 附录引用 |
|---|---|---|---|---|---|---|

完整 AB 表、样本、话术、回填模板放附录 E。

### ④ 附录索引

附录只负责“信息不丢失”，不负责说服读者。每个附录开头先给 3-5 条摘要，再放完整材料。正文只用编号引用附录，例如 `[证据 B-03]`、`[风险 D-02]`、`[实验 E-01]`。

默认包含的附录材料：

- 已确认事实、待确认事实、关键假设、高风险假设。
- 信息来源、证据等级、访问状态。
- Step 0 分流判断和推导路径。
- 行为改变分析、经营模型推导、创意推导。
- 被放弃的方向及原因。
- Red Team 攻击与修正记录。
- 实验计划、交付一致性检查、终审意见。

除非用户明确要求“完整过程逐步展开”，不要输出 Step-by-Step 流水账。

### 聊天内输出

用户没有要求生成文件时，也按“双层”表达：先给“方案正文”，再给“思考过程摘要”。不要混写。

## 三、B 档 · 标准文字版方案

这是默认交付格式。它由「前台说服层 + 创意层 + 执行层 + 管控层」组成，但只输出到干净方案文件；内部推导另写思考过程文件。

### 标准骨架

```
① 封面信息
② 执行摘要
③ 项目背景与核心问题
④ 活动目标与成功判据
⑤ Big Idea 与核心机制
⑥ 活动体验与现场流程
⑦ 传播与转化承接
⑧ 执行规划
⑨ 预算规划
⑩ 风险与合规
⑪ 效果评估
⑫ 待确认事项
```

### ① 封面信息

包含：活动名称、客户/品牌、方案版本、日期、提交方。若用户没有提供，用占位符标「待确认」，不要编造。

### ② 执行摘要

300-500 字，给老板/客户快速判断。必须回答：

- 为什么要做这场活动？
- 核心创意是什么？
- 它优先赢什么指标？
- 预算和执行复杂度大致在哪个档？
- 最大不确定性是什么？

### ③ 项目背景与核心问题

- 背景不是行业废话，要承接 Step 1 的市场信号、Step 2 的真实动机和 Step 5 的创意机制。
- 写清「为什么是现在」，包括热点情绪、竞品空白、用户反向信号或品牌内部资源。
- 只保留最影响决策的 3-5 条依据。完整事实、来源和假设表放入思考过程文件。

### ④ 活动目标与成功判据

- 写一句话业务目标。
- 写主判据、辅助判据、测量方式和负责人。
- 必须说明怎么证明活动有效，但不要把完整四层传导链图和推导路径塞进正文；完整模型放入思考过程文件。

### ⑤ Big Idea 与核心机制

包含主叙事、核心冲突、Big Idea、核心玩法和主场面。创意推导过程、闪卡比较和被否方向放入思考过程文件。

## 四、八节核心内容

以下八节是所有 B/C/D 档方案的核心内容；A 档可压缩成一页。

## ① 一句话 Big Idea

- 一句能脱口而出、能被记住、能被复述的主张。
- 检验：用户听完能不能转述给别人？转述不了，就不是 Big Idea，是描述。
- 必须回溯到 Step 5 选中的创意闪卡，不能在成案阶段变成模板话术。
- 格式：`「主题」—— 一句话主张（含情绪或冲突）`

## ② 目标与传导链判据

- 对齐 Step 3 的一句话业务目标 + 传导链判据，并回扣 Step 2 的目标行为。**判据不是并列 KPI，是四层传导链 × 四维测量**（见 `references/metrics-flow.md`）。
- 每个判据必须是**可验证指标**；优先用数字（到场率、转化数、传播量、签约额），并覆盖「数量 + 质量」两维，结果层还要「效率 + 成本」。没有采集能力时，降级为「可观察信号 + 指定确认人」。不许「提升品牌影响力」这种空话。
- 完整闭环图和推导路径写入思考过程文件；干净方案只保留主判据表和必要解释。
- 格式：`目标一句话 + 判据表（指标 / 目标值 / 怎么测 / 负责人）`

## ③ 体验设计

- **用户旅程**：从「收到邀请」到「离场后 3 天」，分节点写每个时刻用户看到/听到/感到什么。
- **峰值时刻**：设计 1 个「几年后还记得」的高峰瞬间（对齐心理机制）。高预算、年度项目、文化文旅和正式比稿场景必须升级为 `pitch-winning-proposal.md` 里的「年度级记忆点」，单独成页，不得只藏在用户旅程表里。
- **终值时刻**：设计体面收尾（离场小礼物、离场情绪、离场动作），峰终定律决定记忆。
- 格式：`时间轴表（节点 / 用户动作 / 设计动作 / 踩中的心理机制）`

## ④ 传播设计

- **前**：怎么造期待（悬念、预热、KOL 预告）。
- **中**：怎么让到场的人自发传播（打卡点、社交货币、实时话题）。
- **后**：怎么二次发酵（物料复盘、长尾内容、UGC 沉淀）。
- **渠道矩阵**：每个渠道（小红书/抖音/微博/微信/B站/线下）配什么内容、什么节奏。
- **外包接口**：若传播由外部团队、甲方传播部或达人/KOL 承接，必须输出每日或分阶段素材交付表，写清数量、格式、来源模块、交付时间和责任人。
- 格式：`三阶段表 + 渠道矩阵表`

## ④.5 经营模型与交付系统

按 Step 6 触发模块输出，不要全量堆砌：

- 有报名/票务：报名漏斗、表单字段、提醒节奏、签到备份。
- 有赞助/招商：权益矩阵、履约 tracker、赞助商 ROI report。
- 有峰会/论坛/闭门会：session 目标、互动结构、主持收口、会后动作。
- 有大型执行：关键路径、RACI、压缩时间线、交付一致性检查。
- 有数据证明要求：KPI 采集点、工具、负责人、失败备份。

## ⑤ 实验计划

- **承接 Step 5/7 的假设**：从创意闪卡和对抗审查里搬运关键假设，别临时新造。
- **优先测关键假设**：来不来、发不发、买不买、信不信、记不记、跑不跑得通。
- **实验颗粒度跟复杂度走**：A 档设计 1 个快速预检；B 档至少 2 个实验；C/D 档内部形成完整实验计划。干净方案只写关键验证动作、决策时间和失败降级。
- **判据提前写**：主指标、辅助指标、护栏指标、成功阈值、失败降级都要在测试前写清。
- **样本不足要降级表达**：小样本只能叫「方向性预检」，不能叫「验证成功」。
- 干净方案只写关键预检动作、决策时间和失败降级；完整实验表写入思考过程文件。

## ⑥ 执行设计

- **工作范围（正式提案强制）**：写清我方负责什么、用户/甲方需要提供什么、哪些内容不包含在本方案里、哪些事项待确认。
- **倒排时间表（筹备视角）**：从今天到活动日，倒排关键节点（T-30 定场地 → T-14 物料 → T-3 彩排 → D-day）。
- **当天分时排期表（当天视角，别和倒排混成一张）**：活动当天，从开门到散场，按「几点 · 在哪 · 干什么 · 谁出 · 多少钱」逐段排，颗粒度 2 小时（大型活动 1 小时）。
- **环节清单（具体清单层）**：每个环节的「内容清单」——从横纵分析的「细化」动作（`creative-inputs.md` 三）得出内容条目，再查 `industries.md` 的「标准模块」列补默认模块，逐个环节列出「需要哪些内容、细到什么程度」。**框架由拆解得来，值由用户填**。
- **分工**：每个环节一个负责人 + 一个兜底人（RACI 简版）。
- **物料清单**：每个物料 + 数量 + 到位时间。
- **预算表**：分项（场地/搭建/AV/餐饮/嘉宾/宣传/人员/应急）→ 加总 → 应急金比例（默认 10%）。分项侧重参考 `references/industries.md` 的「预算结构」列，别拍脑袋分。高预算正式提案必须先按 `pitch-winning-proposal.md` 输出预算价值架构，把费用解释成系统价值，再列明细。
- 格式：`工作范围 + 倒排时间表 + 当天分时排期表 + 环节清单 + 分工表 + 物料表 + 预算表`

## ⑦ 风险预案

- 从 Step 7 对抗审查的高严重度缺陷直接搬运，每条配预案。
- 每条风险：`风险 / 概率 / 影响 / 预案 A / 预案 B`。
- 至少覆盖：天气、供应商、现场安全、舆情、到场率不达标。
- 涉及大型活动、食品酒类、医疗健康、金融、政企仪式、未成年人、直播电商时，必须额外挂载合规风险。

## ⑧ 效果评估

- 活动后怎么证明「成功判据」达成？每个判据配一个测量方式。
- 干净方案写验收表：`指标 / 目标 / 数据来源 / 负责人 / 复盘时间`。
- 四层回填、实验结论回填、推导路径断点等复盘模板写入思考过程文件。
- **长闭环（强制）**：活动结束后，把「目标 vs 实际 + 断点层 + 翻车点 + 推导路径断点 + 创意类型」追加到 `output/case-library/` 或用户指定复盘文档，供下次 Step 1 / Step 5 检索。跑测偏差写入 `output/run-reviews/`，Skill 改进建议写入 `output/improvement-log/`。不得直接写回 `references/event-types.md` 或其他 `references/` 方法论文件。

## 五、活动类型模块挂载表

先按 `event-types.md` 定主类型，再从下表挂载模块。主类型 1 个，辅类型不超过 2 个。不要全表照搬。

| 活动类型 | 必选模块 | 强化模块 |
|---|---|---|
| 发布会 | 新闻点、产品/品牌叙事、媒体传播、现场峰值、Q&A | 媒体邀约、嘉宾动线、发布节奏、舆情预案 |
| 招商会 | 信任背书、政策/利益设计、逼单节奏、签约机制 | 渠道分层、线索评级、会后跟进、签约物料 |
| 年会 | 主题叙事、情绪峰值、表彰机制、节目流程 | 员工参与、领导发言包装、奖项故事、氛围物料 |
| 团建/内部沙龙 | 破冰机制、协作任务、轻量流程、参与边界 | 低尴尬设计、休息时间保护、反馈收集 |
| 快闪/市集 | 稀缺感、打卡点、动线、社交传播、转化承接 | 摊位规划、人流预估、天气/城管/消防预案 |
| 峰会/论坛 | 议题体系、嘉宾阵容、议程设计、参会价值 | 主持串词、圆桌问题、招商/赞助权益、媒体通稿 |
| 展会/展览 | 展位体验、展陈逻辑、获客路径、物料清单 | 留资机制、讲解话术、撤展计划、展商服务 |
| 私享会/品鉴会 | 圈层定位、邀约理由、体验流程、关系经营 | VIP 分层、伴手礼、会后跟进、成交承接 |
| 直播带货 | 货盘、主播信任、节奏逼单、优惠机制 | 脚本、场控、投流、售后/退货预案 |
| 公益/CSR | 价值观、受益者、参与机制、透明度 | 公信背书、捐赠/数据披露、作秀风险 |
| 政企/仪式类 | 规格、领导动线、仪式动作、传播口径 | 报批、安保、新闻通稿、座次礼仪 |

## 九、交付格式

- 终审通过后，且用户明确要求 docx / Word / 可下载文件时，才输出 .docx 交付（借力本地 docx 生成能力，见 `references/skill-routing.md`）。
- docx 内容 = 所选档位正文 + 必要执行附录。闭环图默认留在思考过程文件；用户明确要求放入 docx 时再转成四层链表格。
- markdown 源稿保留，作为 docx 的生成依据。
- 检索不到 docx 能力时，输出 markdown 并明确告知「未生成 docx」；不得因为无法导出 docx 而跳过 Step 9。
- 当生成两个 markdown 时，docx 默认只导出干净方案；思考过程只在用户明确要求时导出。

## 十、输出纪律

1. **先判档位**：不判断 A/B/C/D 就直接写方案，是输出失控。
2. **先给最小可执行版本**：轻量活动别套大型活动流程，每个环节先问「能不能砍」。
3. **说服层和执行层分开**：执行摘要给老板/客户看，执行表给团队看，不要混成一锅。
4. **正式提案必须有工作范围**：谁负责什么、甲方提供什么、哪些待确认，必须写清。
5. **预算必须算术自检**：分项加总 = 总额 + 应急金，对不上就是算错了。
6. **合规必须联网核实**：报批、消防、许可、广告法，不熟悉的行业别凭印象写。
7. **每节都要能落地**：写到「谁、什么时间、做什么、花多少钱」，不许停留在「要加强」「要重视」。
8. **闭环图必做但不必进正文**：B/C/D 档必须在思考过程文件保留四层传导链；干净方案只写主判据和验收方式。
9. **实验计划必做但要分层**：B/C/D 档必须设计关键假设预检；干净方案只写关键动作和决策点，完整实验表进思考过程。
10. **推导路径必验但不污染方案**：推导路径和断点检查写入思考过程文件，除非用户要求，不放入正式方案正文。
11. **创意不能被磨平**：Big Idea、峰值时刻、传播钩子、现场动作必须能回溯到 Step 5 的创意闪卡。
12. **叙事不能空心**：主叙事、核心冲突和主场面必须能落到现场动作、传播资产和预算支撑。
13. **事实不能漂浮**：预算、案例、指标、政策、嘉宾、媒体、赞助报价必须有证据等级、访问方式/状态或待确认标记。
14. **交付必须一致**：人数、预算、时间、权益、数据、销售承接互相矛盾时，不得判“可上交”。
