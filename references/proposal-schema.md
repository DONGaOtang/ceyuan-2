# 活动方案最终结构模板

供 Step 5 输出文字版活动方案时使用。核心原则：**文字版方案不是单一模板，而是按用途裁剪的交付系统。** 先判断交付格式，再选择模块；不要给轻量活动套全案，也不要给正式提案漏掉说服层和工作范围。

## 一、交付格式分级

进入 Step 5 先选交付格式。若用户没有指定，按活动复杂度和阅读对象默认选择。

| 档位 | 适用场景 | 读者 | 输出重点 |
|---|---|---|---|
| A · 一页创意提案 | 早期沟通、老板先看方向、用户只要创意 | 老板 / 客户 / 内部拍板人 | 快速判断有没有感觉、值不值得继续 |
| B · 标准文字版方案 | 大多数活动策划交付 | 客户 / 市场部 / 项目负责人 | 说清为什么做、怎么做、怎么衡量 |
| C · 全案执行版 | L3 大型活动、跨部门协作、供应商落地 | 执行团队 / 供应商 / 项目管理者 | 让团队按表推进，不靠口头解释 |
| D · 对外竞标/招商/赞助提案 | 竞标、赞助招商、政府/合作方提案 | 客户 / 赞助商 / 合作方 / 政企对象 | 说服对方投入钱、资源或背书 |

**裁剪规则**：

- L1 轻量活动默认 A 或 B，除非用户明确要执行全案。
- L2 标准活动默认 B，按活动类型挂载必要模块。
- L3 全案默认 C；若方案用于竞标、招商或赞助，同时叠加 D 的商务模块。
- 用户只要创意，不输出完整长方案，先给 A 档。
- 用户要 docx，先生成对应档位的 markdown 源稿，再导出。

## 二、A 档 · 一页创意提案

适合快速过方向。控制在一页或 800 字以内。

```
① 活动背景一句话
② 目标一句话
③ Big Idea
④ 3 个核心玩法
⑤ 为什么现在做
⑥ 预期效果
⑦ 最大风险
⑧ 下一步待确认
```

**输出纪律**：

- 不写长执行表。
- 每个玩法必须有现场动作或传播动作。
- 最大风险必须诚实写，不许只写好处。

## 三、B 档 · 标准文字版方案

这是默认交付格式。它由「前台说服层 + 创意层 + 执行层 + 管控层」组成。

### 标准骨架

```
① 封面信息
② 执行摘要
③ 活动背景与洞察
④ 目标与传导链判据（含闭环图）
⑤ Big Idea 与创意推导
⑥ 受众与参与路径
⑦ 体验设计（用户旅程 + 峰终时刻）
⑧ 传播设计（前中后 + 渠道矩阵）
⑨ 实验计划（AB 测试 / 最小预检 / 失败降级）
⑩ 执行设计（时间线 / 分工 / 物料 / 预算表）
⑪ 风险预案
⑫ 效果评估（四层回填 + 实验结论回填）
⑬ 待确认事项
```

### ① 封面信息

包含：活动名称、客户/品牌、方案版本、日期、提交方。若用户没有提供，用占位符标「待确认」，不要编造。

### ② 执行摘要

300-500 字，给老板/客户快速判断。必须回答：

- 为什么要做这场活动？
- 核心创意是什么？
- 它优先赢什么指标？
- 预算和执行复杂度大致在哪个档？
- 最大不确定性是什么？

### ③ 活动背景与洞察

- 背景不是行业废话，要承接 Step 1 的真实动机和 Step 3 的市场信息碰撞。
- 写清「为什么是现在」，包括热点情绪、竞品空白、用户反向信号或品牌内部资源。
- 具体建议与案例参考分开标注；案例只能当参照，不许照搬。

## 四、八节核心内容

以下八节是所有 B/C/D 档方案的核心内容；A 档可压缩成一页。

## ① 一句话 Big Idea

- 一句能脱口而出、能被记住、能被复述的主张。
- 检验：用户听完能不能转述给别人？转述不了，就不是 Big Idea，是描述。
- 必须回溯到 Step 3 选中的创意闪卡，不能在成型阶段变成模板话术。
- 格式：`「主题」—— 一句话主张（含情绪或冲突）`

## ② 目标与传导链判据

- 对齐 Step 2 的一句话目标 + 传导链判据。**判据不是并列 KPI，是四层传导链 × 四维测量**（见 `references/metrics-flow.md`）。
- 每个判据必须是**数字**（到场率、转化数、传播量、签约额），且覆盖「数量 + 质量」两维，结果层还要「效率 + 成本」。不许「提升品牌影响力」这种空话。
- **闭环图（强制）**：产出一张「投入 → 中间指标 → 结果指标 → 长线资产」四层传导图，标出主判据在哪层、由哪几个中间指标驱动。根据动机动态生成（卖货重心在结果层，品牌重心在资产层，关系重心在中间层）。
- **推导路径（强制）**：方案开头标注整体推导路径 `[七状态] → [参与者/受益者] → [形态] → [时空]`（见 `references/axes.md` 六），让类型定位可被检查。
- 格式：`目标一句话 + 推导路径 + 传导链判据表（层级 / 指标 / 目标值 / 怎么测）+ 闭环图（mermaid 或 ASCII，docx 里转表格）`

## ③ 体验设计

- **用户旅程**：从「收到邀请」到「离场后 3 天」，分节点写每个时刻用户看到/听到/感到什么。
- **峰值时刻**：设计 1 个「几年后还记得」的高峰瞬间（对齐心理机制）。
- **终值时刻**：设计体面收尾（离场小礼物、离场情绪、离场动作），峰终定律决定记忆。
- 格式：`时间轴表（节点 / 用户动作 / 设计动作 / 踩中的心理机制）`

## ④ 传播设计

- **前**：怎么造期待（悬念、预热、KOL 预告）。
- **中**：怎么让到场的人自发传播（打卡点、社交货币、实时话题）。
- **后**：怎么二次发酵（物料复盘、长尾内容、UGC 沉淀）。
- **渠道矩阵**：每个渠道（小红书/抖音/微博/微信/B站/线下）配什么内容、什么节奏。
- 格式：`三阶段表 + 渠道矩阵表`

## ⑤ 实验计划

- **承接 Step 3/4 的假设**：从创意闪卡和对抗审查里搬运关键假设，别临时新造。
- **优先测关键假设**：来不来、发不发、买不买、信不信、记不记、跑不跑得通。
- **实验颗粒度跟复杂度走**：A 档写 1 个快速预检；B 档至少 2 个实验；C/D 档输出完整实验计划。
- **判据提前写**：主指标、辅助指标、护栏指标、成功阈值、失败降级都要在测试前写清。
- **样本不足要降级表达**：小样本只能叫「方向性预检」，不能叫「验证成功」。
- 格式：`假设 / 变量 / A版 / B版 / 渠道样本 / 判据 / 成功阈值 / 失败降级 / 决策时间`

## ⑥ 执行设计

- **工作范围（正式提案强制）**：写清我方负责什么、用户/甲方需要提供什么、哪些内容不包含在本方案里、哪些事项待确认。
- **倒排时间表（筹备视角）**：从今天到活动日，倒排关键节点（T-30 定场地 → T-14 物料 → T-3 彩排 → D-day）。
- **当天分时排期表（当天视角，别和倒排混成一张）**：活动当天，从开门到散场，按「几点 · 在哪 · 干什么 · 谁出 · 多少钱」逐段排，颗粒度 2 小时（大型活动 1 小时）。
- **环节清单（具体清单层）**：每个环节的「内容清单」——从横纵分析的「细化」动作（`creative-inputs.md` 三）得出内容条目，再查 `industries.md` 的「标准模块」列补默认模块，逐个环节列出「需要哪些内容、细到什么程度」。**框架由拆解得来，值由用户填**。
- **分工**：每个环节一个负责人 + 一个兜底人（RACI 简版）。
- **物料清单**：每个物料 + 数量 + 到位时间。
- **预算表**：分项（场地/搭建/AV/餐饮/嘉宾/宣传/人员/应急）→ 加总 → 应急金比例（默认 10%）。分项侧重参考 `references/industries.md` 的「预算结构」列，别拍脑袋分。
- 格式：`工作范围 + 倒排时间表 + 当天分时排期表 + 环节清单 + 分工表 + 物料表 + 预算表`

## ⑦ 风险预案

- 从 Step 4 对抗审查的高严重度缺陷直接搬运，每条配预案。
- 每条风险：`风险 / 概率 / 影响 / 预案 A / 预案 B`。
- 至少覆盖：天气、供应商、现场安全、舆情、到场率不达标。
- 涉及大型活动、食品酒类、医疗健康、金融、政企仪式、未成年人、直播电商时，必须额外挂载合规风险。

## ⑧ 效果评估

- 活动后怎么证明「成功判据」达成？每个判据配一个测量方式。
- **四层回填（强制，见 `references/metrics-flow.md` 四）**：复盘时逐层填「目标 vs 实际」——投入层花对了吗 / 中间指标层达标了吗 / 结果指标层主判据赢了吗 / 长线资产层沉淀了什么。**断在哪层，下次就补哪层**。
- **实验结论回填（强制，见 `references/experiment-validation.md` 六）**：复盘时回填「原假设 → 测试版本 → 测试结果 → 实际活动表现 → 结论 → 下次复用/禁用」。实验结果和最终结果不一致时，要判断是样本错、渠道错、执行错，还是现场变量改变。
- **推导路径回填（强制）**：复盘时对一遍「推导路径」——Step 3 定位的类型，实际跑下来还成立吗？定位偏了吗（比如以为是想卖货，实际是想确认身份）？偏了就是「推导路径断点」。
- 复盘模板：`目标 vs 实际 / 实验结论 / 差在哪 / 为什么 / 下次怎么改 / 断点在哪层 / 推导路径断点在哪`。
- **长闭环（强制）**：活动结束后，把「目标 vs 实际 + 断点层 + 翻车点 + 推导路径断点 + 创意类型」追加到 `references/event-types.md` 对应活动类型的案例锚点里，供下次 Step 1 / Step 3 检索。不写回 = 这次活动白做，下次从零开始。

## 六、C 档 · 全案执行版增强模块

- 项目组织架构
- RACI 分工表
- 供应商/场地方/嘉宾/媒体管理
- 详细倒排甘特表
- 当天分钟级 Run of Show
- 物料矩阵
- 人员点位图
- 安保/消防/医疗/舆情预案
- 合规与审批清单
- 复盘数据采集表

## 七、D 档 · 对外竞标/招商/赞助提案增强模块

- 权益包设计

## 九、交付格式

- 终审通过后，输出 .docx 交付（借力本地 docx 生成能力，见 `references/skill-routing.md`）。
- docx 内容 = 所选档位正文 + 必要附录表 + 闭环图（四层链转成表格）。
- markdown 源稿保留，作为 docx 的生成依据。
- 检索不到 docx 能力时，输出 markdown 并明确告知「未生成 docx，可自行转换」。

## 十、输出纪律

1. **先判档位**：不判断 A/B/C/D 就直接写方案，是输出失控。
2. **先给最小可执行版本**：轻量活动别套大型活动流程，每个环节先问「能不能砍」。
3. **说服层和执行层分开**：执行摘要给老板/客户看，执行表给团队看，不要混成一锅。
4. **正式提案必须有工作范围**：谁负责什么、甲方提供什么、哪些待确认，必须写清。
5. **预算必须算术自检**：分项加总 = 总额 + 应急金，对不上就是算错了。
6. **合规必须联网核实**：报批、消防、许可、广告法，不熟悉的行业别凭印象写。
7. **每节都要能落地**：写到「谁、什么时间、做什么、花多少钱」，不许停留在「要加强」「要重视」。
8. **闭环图必带**：没有四层传导链闭环图的 B/C/D 档方案，不算完整方案。
9. **实验计划必带**：B/C/D 档没有关键假设实验计划，不算完整方案；A 档没有快速预检，不算稳妥提案。
10. **推导路径必验**：方案开头有推导路径，结尾验证推导路径没跑偏，没有这两处的方案不算完整。
11. **创意不能被磨平**：Big Idea、峰值时刻、传播钩子、现场动作必须能回溯到 Step 3 的创意闪卡。
