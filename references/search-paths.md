# 检索路径库（活水地图）

供 Step 1 信息采集与横纵分析、Step 5 创意机制前加载。核心一句话：**对的问题，先由 AI 选择最小必要信息源并自动验证；只有账号、权限、验证码、付费墙等人类必须介入节点，才请求用户取舍。**

本文件是“活水地图 + 来源路由”，不是采集保证书。具体访问、登录、截图、降级和证据状态按 `source-access-and-login-workflow.md` 执行。

## 一、先判断要什么（信号路由）

检索前先问：这一步要的到底是哪种信息？不同问题，去不同源，别搞反。

| 要什么 | 优先源 | 别去 |
|---|---|---|
| 案例灵感 | 数英网 / SocialBeta / 广告门 / 新榜公开页 / 品牌官方号 | 只看新闻稿 |
| 用户真实口碑 | 小红书 / 抖音评论区 / 微博 / 知乎 / B站弹幕与评论 | 官方宣传稿 |
| 热点趋势 | 微博热搜 / 抖音热榜 / 新榜日榜 / 百度指数 | 旧报告 |
| 创意碰撞信号 | 小红书笔记/评论、抖音挑战/评论、B站弹幕、微博话题、竞品活动回顾 | 只看案例标题 |
| 行业数据 | 公开报告 / 艾瑞公开内容 / 行业协会 / 蝉妈妈 / QuestMobile / 卡思数据 | 自媒体猜测 |

铁律：要口碑、反应、真实想法，不能只用搜索引擎搜新闻。新闻稿经常夸大、漏掉真实用户声音。

## 二、来源可访问性分层

| 层级 | 含义 | 示例 | 采集方式 |
|---|---|---|---|
| A 类：公开网页源 | 普通联网搜索或网页访问通常可验证 | 政府官网、品牌官网、公开新闻、公开行业报告、部分案例库页面 | 联网搜索、网页读取、链接核验 |
| B 类：浏览器验证源 | 需要站内搜索、滚动、点击、截图、评论区核验 | 小红书、抖音、微博、B站、知乎 | 浏览器自动化；必要时用户登录 |
| C 类：登录/权限/付费源 | 需要账号、会员、后台、机构权限或 API | 蝉妈妈、QuestMobile、卡思数据、新榜后台、舆情监测平台 | 需账号权限；不可访问时标待验证 |

B/C 类是真实来源，但不等于稳定可自动采集。抓不到、登录墙、403、验证码、内容不支持判断时，必须按 `source-access-and-login-workflow.md` 降级。

## 三、级联优先级

每个平台按以下顺序走，上层不行再降级：

1. **平台站内直搜**：有浏览器能力且平台可访问时优先，适合拿一手声音。
2. **搜索引擎 `site:` 限定**：站内搜不可用、未登录或结果不稳定时，用 `活动词 site:平台域名` 补漏。
3. **公开案例/官方/媒体/报告源**：用于补事实、背景和案例机制。
4. **第三方聚合/数据平台**：用于规模统计或行业趋势；没有账号权限时只列为候选源。

颠倒级联是失败模式。但如果站内直搜被登录墙或风控挡住，不能卡住用户，必须自动降级。

## 四、中文活动策划的检索路径

### 案例 / 灵感源

- 数英网、SocialBeta、广告门、新榜公开内容、卡思公开报告：搜“品类词 + 活动词”。
- 品牌官方账号（公众号 / 微博 / B站 / 官网）：看品牌自己如何定义活动和传播口径。
- 同类活动复盘、参会者笔记、媒体原创报道：拆机制，不照搬环节。

### 用户口碑源

- 小红书：站内搜“品类 + 活动词”，看笔记与评论；未登录时先检测能否看到结果。
- 抖音：搜话题/挑战赛，看评论区、点赞、互动和可见完播线索；不可见时标限制。
- 微博：搜活动话题，看实时讨论、转发链、吐槽和媒体扩散。
- 知乎：搜相关问题，看长回答与争议点。
- B站：搜活动视频，看弹幕、评论区、二创和长评。

至少交叉 2-3 个平台。只有一个平台反复出现的口碑，只能算中信号。

### 热点趋势源

- 微博热搜、抖音热榜、新榜日榜、百度指数。
- Step 5 跑交叉网络前，先按 `source-access-and-login-workflow.md` 检测热点源访问状态，再提取热点背后的情绪。借势不是贴热点名，而是把情绪喂给 H 热点域和 E 情绪域。

### 行业数据源

- 公开报告、行业协会、政府统计、公司财报、品牌官方数据。
- 蝉妈妈、QuestMobile、艾瑞、卡思数据、新榜等平台需要先判断公开可见、登录可见、付费可见还是权限不可达。
- 没有权限时，不得编行业数据，只能写“需账号权限/待验证”。

### 非消费端垂直源

消费端源不适合所有活动。政企招商、校招、危机公关、开工仪式、线上活动要换源。

| 活动类型 | 垂直源 |
|---|---|
| 政企招商 / 政府关系 | 政府官网、招商局网站、产业园公告、地方党媒 |
| 招聘 / 雇主品牌 | 招聘平台、脉脉、牛客、雇主品牌报告、Glassdoor 类点评 |
| 危机公关 / 舆情 | 舆情监测平台、主流媒体评论、监管公告、黑猫投诉 |
| 仪式型（开工/签约/揭牌） | 政府新闻、行业垂直媒体、地方电视台 |
| 线上 / 混合活动 | 平台线上活动数据、完播率/参会率数据源、B端活动平台 |

## 五、反模式

1. 用新闻稿/官方宣传代替真实口碑。
2. 只搜一个平台就下结论。
3. 报数据不引用原文或访问状态。
4. 过滤负面评价来“平衡”。
5. 不查一手来源就用二手转载。
6. 把登录墙、搜索结果页、热榜标题写成完整事实。
7. 让用户自己去搜资料，而不是 AI 先验证再请求最小介入。

## 六、来源验证

每个来源引用前必须确认：

1. 链接或页面真实存在，不是 404/403。
2. 内容确实支持引用，不是只标题相似。
3. 评论区、热榜、平台数据能否真实看到。
4. 访问方式和访问状态已经记录。
5. 抓不到的，诚实标注“待验证”“需登录”“需账号权限”或“访问受限”。

输出时逐条绑定：

| 事实/信号 | 来源名称与链接或用户原话 | 日期/检索时间 | 访问方式/状态 | 证据等级 | 对方案影响 |
|---|---|---|---|---|---|

禁止只在文末堆来源。

## 七、输出格式（按信号强度分层）

检索完，按信号强度分层输出：

- **Tier S**：多个独立来源都说同一件事，且访问状态支持判断，可采信。
- **Tier A**：反复出现，但来源单一或访问受限，中信号，标注存疑。
- **Tier C**：反向信号，用户讨厌、吐槽、抵触或觉得尴尬的点。

必须包含 Tier C。用户讨厌什么，往往直接决定创意该避开什么。
